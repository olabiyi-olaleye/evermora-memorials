# generateShareAsset

**Status — IMPLEMENTED** (Phase 5J). Executable, unit- and integration-tested.
`retireShareAsset` retires one.

**Purpose** — Mint a **permanent** share/QR identifier (`share_resolvers` row)
for a memorial — for a funeral programme, memorial card, banner, reception
table, or keepsake.

**Business responsibility** — A printed QR must keep working forever, even if
the slug, the name, or internal routing changes — so it points at a permanent
token, never at a slug.

## Caller context / Input / Output

|        |                                                                                                                                                                          |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Caller | authenticated; `memorial.edit` or platform admin                                                                                                                         |
| Input  | `memorialId`, `label?` (≤ 120, sanitised), `medium?` (`funeral_programme` \| `memorial_card` \| `banner` \| `reception_table` \| `keepsake` \| `other`, default `other`) |
| Output | `{ shareResolver: ShareResolverRow }` — `token` is an 18-hex-char permanent identifier                                                                                   |

The transport composes the URL (`{APP_URL}/q/{token}`) and the QR image
(`@evermora/utils` `qrSvg` — a self-contained SVG, no external service). The
domain returns data only.

## Authentication / Authorization

`UnauthenticatedError`; then `requireMemorialPermission(memorialId, 'memorial.edit')`
— `MemorialNotFoundError` / `ForbiddenError` / `MemorialInvalidStateError`.
`feature_settings.qr_code_enabled` must be on, else
`PreconditionFailedError { reason: "qr_disabled" }`.

## Validation / Invariants / Preconditions

- `token` is generated by the persistence adapter (`randomBytes(9).toString("hex")`),
  unique, and matches the DB `share_resolvers_token_shape` check (`^[a-f0-9]{12,}$`).
- Multiple resolvers per memorial are allowed — one per print run.
- A resolver is retired (`is_active = false`, `retired_at`), **never deleted** —
  a printed card in the world still resolves, to a gentle notice.

## Database interactions / Transaction

One transaction-scoped-RLS unit of work: `insert into share_resolvers` + one
`audit_logs` row. QR image generation happens **outside** the domain.

## Resolution (read side — `resolve_share_token`, IMPLEMENTED since Phase 2)

`public.resolve_share_token(token)` → `(memorial_id, canonical_slug, is_active)`.
`apps/web` `/q/[token]`: active → redirect to `/{canonical_slug}`; retired /
not-public → respectful notice; unknown → 404.

## Side effects / Events

- **Domain event** `share_asset.generated` `{ memorialId, shareResolverId, medium }`.
- **Audit** `share_asset.generated`; `share_asset.retired` on retire.
- **Notification** none.

## Errors

`unauthenticated` · `forbidden` · `not_found` · `validation` · `precondition_failed`
(QR disabled) · `internal`.

## Idempotency

Not idempotent — each call is a new token (a new print run). `retireShareAsset`
on an already-retired resolver is a no-op (no second audit row).

## Security considerations

The token is a bearer capability to reach a **public** memorial only — no family
access, nothing private. The QR SVG is generated from a URL the server controls
and contains no external references.
