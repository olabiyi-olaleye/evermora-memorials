# Security architecture

Evermora holds grief-adjacent, family-private data. This document is the
security model; each control is marked **IMPLEMENTED** or **PLANNED** — do not
read a planned control as an existing one.

## Threat model (summary)

| Actor                                                      | Wants                                                 | Primary controls                                                                                                                                                        |
| ---------------------------------------------------------- | ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Curious visitor                                            | see private / draft memorials, other visitors' emails | RLS, private columns via row scope + SECURITY DEFINER views                                                                                                             |
| Malicious visitor                                          | forge tributes/audit rows, spam, abusive uploads, XSS | RLS `WITH CHECK`, no anon insert on `audit_logs`/`notifications`, per-IP rate limiting on every anon-write operation, upload validation (PLANNED), output encoding, CSP |
| Compromised family member (lower role)                     | act above their role, take ownership                  | domain checks + RLS `has_memorial_permission`, ownership-transfer guard, last-owner guard                                                                               |
| Compromised family account                                 | exfiltrate/deface a memorial                          | per-memorial scoping, audit trail, platform suspension path                                                                                                             |
| Attacker with a leaked `anon` key                          | anything                                              | `anon` key is **not** a secret; RLS is the boundary; least-privilege grants                                                                                             |
| Attacker with a leaked `service_role` key / `DATABASE_URL` | full DB access                                        | server-only, never `NEXT_PUBLIC_`, env proxy guard, rotate on exposure                                                                                                  |
| Platform insider mistake                                   | broad client policy, seed against prod                | explicit platform-admin path, guards short-circuit only for non-end-users, fictional local-only seed                                                                    |

| **Env boundary** — Zod `createEnv` splits client/server, throws on a browser read of a server key; server keys never `NEXT_PUBLIC_`                                                                                                                                                                                                                          | `@evermora/config`                                                                                                                                                                  |

| **Secret hygiene** — `.env*` git-ignored, `.env.example` placeholders only, `redactConnectionString()` helper, no secret in transcript/report/logs                                                                                                                                                                                                           | `.gitignore`, `@evermora/database`                                                                                                                                                  |

| **Per-IP rate limiting on every anon-write operation** — `submitTribute` (5G), `reportTribute` and `requestFuneralService` (Phase 5O). Each is a SECURITY DEFINER count function (`recent_*_from_ip`) so `anon` can rate-limit itself without a `SELECT` grant on the base table; `reports`/`service_requests` gained a private `submitted_ip` column for it | `…_rate_limit_reports_and_services.sql`, [report-tribute.md](../domain/operations/report-tribute.md), [request-funeral-service.md](../domain/operations/request-funeral-service.md) |
| **Malicious-URL handling** — a funeral event's `livestreamUrl` is scheme-restricted to `http:`/`https:` (`isSafeHttpUrl`), rejecting `javascript:`/`data:`/`vbscript:`/`file:`; rendered with `rel="noopener noreferrer"`, `target="_blank"`                                                                                                                 | `packages/utils/src/url.ts`, [save-funeral-event.md](../domain/operations/save-funeral-event.md)                                                                                    |
| **Security headers / CSP** — static `Content-Security-Policy` (`default-src 'self'`, `frame-ancestors 'none'`, `object-src 'none'`, no `'unsafe-eval'` in production), `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `Strict-Transport-Security` on all 3 apps                                                       | `apps/*/next.config.ts`                                                                                                                                                             |
| **Dependency audit gate** — `npm audit --omit=dev --audit-level=high` on every PR, scoped to production dependencies                                                                                                                                                                                                                                         | `.github/workflows/ci.yml`                                                                                                                                                          |

## Planned controls (NOT yet implemented — do not assume otherwise)

| Control                          | Notes                                                                                                                                                                                                                                                                                        |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **CAPTCHA / bot defence**        | **§99 stop — needs a paid provider decision** (hCaptcha / Turnstile / reCAPTCHA) on anon submission forms; Supabase Auth `[auth.captcha]` for sign-up. `deps.captcha` is already a wired-but-empty seam in `submitTribute` — see [submit-tribute.md](../domain/operations/submit-tribute.md) |
| **Spam / abuse filtering**       | content heuristics + link limits on tributes; the `reports` table + `report_status` workflow is the human backstop                                                                                                                                                                           |
| **Upload validation**            | magic-byte MIME check, dimension caps, EXIF-GPS stripping, purpose/bucket match — see [media-storage.md](./media-storage.md)                                                                                                                                                                 |
| **Nonce-based CSP**              | the current CSP is static (`'unsafe-inline'` on script-src/style-src, no nonce) — a nonce requires dynamic rendering on every route, which would cost `apps/web`'s memorial pages their static/ISR caching; a real tradeoff, not taken on silently                                           |
| **CSRF**                         | Server Actions carry Next.js' built-in protection; Route Handlers that mutate need explicit origin checks / tokens                                                                                                                                                                           |
| **Session security**             | short-lived access tokens + rotation (configured), re-auth for sensitive actions (ownership transfer, privacy downgrade, admin), idle timeout for platform-admin                                                                                                                             |
| **Platform-admin MFA**           | required before real admin data — `[auth.mfa]`                                                                                                                                                                                                                                               |
| **Vercel Deployment Protection** | re-enable for `evermora-family` / `evermora-admin` before real data — [vercel-deployment-protection.md](./vercel-deployment-protection.md)                                                                                                                                                   |
| **Secrets management**           | Vercel/Supabase env stores; rotation runbook; no secrets in CI logs                                                                                                                                                                                                                          |
| **Backups / DR**                 | Supabase automated backups (plan-dependent); documented restore drill                                                                                                                                                                                                                        |

## Incident basics

- A leaked secret is **compromised** — rotate it (Supabase dashboard for
  DB password / service key; `vercel logout && vercel login` for the CLI
  session). Removing it from the latest commit is **not** sufficient.
- Abuse on a memorial: platform staff can set `memorials.status = 'suspended'`
  (guard allows only platform admins), which `can_read_memorial` immediately
  enforces; the action is audited.
